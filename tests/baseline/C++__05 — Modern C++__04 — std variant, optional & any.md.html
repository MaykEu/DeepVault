std::variant, optional & any

Why This Matters
A third of game bugs trace to invalid state: health = −1 meaning both "dead" and "uninitialized." A pointer that's nullptr where you forgot to check. A union where you read the wrong member. std::variant, std::optional, and std::any make invalid states unrepresentable. You can't forget to check an optional — you must explicitly unwrap it. You can't read the wrong variant alternative — std::visit forces exhaustive handling. These types encode intent in the type system so the compiler catches mistakes before they ship.

std::variant — The Type-Safe Union

A C union stores one of several types — but doesn't track which. std::variant adds a discriminator (integer tracking the active alternative):

std::variant<int, float, std::string> v;
v = 42;                    // holds int, discriminator=0
v = 3.14f;                 // holds float, discriminator=1 (old int destroyed)
v = std::string("hello");  // holds string, discriminator=2

Memory Layout

┌────────────────────────┐
│  Discriminator (size_t) │  ← 0=int, 1=float, 2=string
├────────────────────────┤
│  Storage buffer         │  ← max(sizeof(int), sizeof(float), sizeof(string))
│  (max alternative)      │     + alignment padding
└────────────────────────┘
Total ≈ sizeof(discriminator) + max(sizeof(alternatives)...) + alignment

Inline storage — no heap allocation for any alternative. If all alternatives are stack-friendly, the variant is stack-friendly.

Accessing

int i = std::get<int>(v);          // Throws std::bad_variant_access if wrong type
int* p = std::get_if<int>(&v);     // Returns nullptr if wrong type — no exception
if (std::holds_alternative<int>(v)) { /* safe */ }

Never std::get without knowing the type in hot paths. Use std::get_if or std::visit.

std::visit — Compile-Time Exhaustive Dispatch

using Property = std::variant<int, float, std::string, bool>;
void Print(const Property& p) {
 std::visit([](const auto& val) { std::cout << val << '\n'; }, p);
}

The compiler generates a dispatch table mapping discriminator → function pointer — essentially a switch over alternatives. If you add a new type to the variant, std::visit won't compile until the lambda handles it — exhaustiveness enforced at compile time.

Overload pattern for per-type logic: 

template<class... Ts> struct overloaded : Ts... { using Ts::operator()...; };
std::visit(overloaded{
 [](int i)       { /* handle int */ },
 [](float f)     { /* handle float */ },
 [](const auto&) { /* default */ }
}, prop);

std::optional — A Value That Might Not Exist

std::optional contains either a T or nothing (std::nullopt). Zero heap allocation.

std::optional<int> FindPlayer(const std::string& name) {
 if (name == "Mario") return 42;
 return std::nullopt;
}
auto result = FindPlayer("Luigi");
if (result) {                   // bool conversion
 int id = result.value();    // Throws std::bad_optional_access if empty
 int id2 = *result;          // UB if empty — check first!
 int id3 = result.value_or(-1); // Safe fallback
}

Memory Layout

┌──────────────────────┐
│  bool has_value       │  ← 1 byte (+ padding)
├──────────────────────┤
│  T value              │  ← Inline — sizeof(T)
└──────────────────────┘
sizeof(std::optional<int>) ≈ 8  (bool + padding + int)

optional is NOT a pointer — no heap, no indirection. An optional is 8 bytes on the stack. A unique_ptr is 8 bytes (pointer) + 4 bytes (heap int) + allocation overhead.

Use optionalUse T* or unique_ptr
T is small (fits in registers)T is large (heap desired)
"Not found" is normalnullptr has established API meaning
Value semantics wantedReference/polymorphism needed

std::any — Type-Erased Any Value

std::any can hold any copyable type. Unlike variant, the set of types isn't specified at compile time. Unlike optional, it stores type information at runtime (RTTI).

std::any a = 42;                // holds int
a = 3.14;                       // now holds double
a = std::string("hello");       // now holds string

Memory — Heap Allocation + RTTI

For types larger than ~sizeof(void), std::any heap-allocates. It stores a pointer, a type_info (RTTI), and a handler function for copy/destroy.

int i = std::any_cast<int>(a);        // Throws std::bad_any_cast if wrong type
if (a.type() == typeid(int)) { /* safe */ }

std::any_cast uses typeid — a runtime check. Unlike std::visit which is compile-time exhaustive.

When to use: scripting engine value bags, plugin APIs where types aren't enumerable. For most game code, std::variant is better — known types, compile-time safety.

Two-Way Explanation

Simple

std::variant is a box containing one item from a known list — like a vending machine with a light showing which product is inside. std::visit is the universal button that calls the right handler for the current product. std::optional is a box that might be empty — like a gift box that either has a present or is just paper. You must check before opening. std::any is a black box with a label maker — can hold anything, but you can only read it if you know the label. Use variant when you know the menu, optional when something might be missing, any only when you truly can't enumerate the types.

Technical

std::variant is a discriminated union: inline storage of max(sizeof(Ts)...) + discriminator (size_t). Access via std::get (throws), std::get_if (nullptr, no exception), or std::visit (compile-time dispatch table — exhaustive). std::optional stores bool + aligned T inline — no heap, sizeof ≈ sizeof(T)+alignment. std::any type-erases via heap allocation + RTTI (typeid); small types may use SBO. UE equivalents: TVariant, TOptional. Use variant for closed-set unions, optional for nullable values, any only for open-ended type erasure.
