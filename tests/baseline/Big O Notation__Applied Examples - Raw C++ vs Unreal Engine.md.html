1. Constant Time: $O(1)$

Raw C++ Structural Pattern

  • The Mechanism: Direct memory address calculation via pointer arithmetic. When you look up an element by its index, the CPU computes the target location using a simple mathematical formula: $\text{Base Address} + (\text{Index} \times \text{Element Size})$. It skips checking any other items in memory.
  • Structural Layout: A flat sequence of instructions with zero tracking loops or conditional branching paths that scale with data size.

Unreal Engine Framework Architecture

  • TArray Direct Indexing: Accessing an element via its integer index (e.g., MyArray[3]).
  • TMap / TSet Key Lookup: Querying a component or spec using a pre-calculated hash key. The engine transforms the key into an integer bucket address instantly.
  • Ability Handles: Activating a gameplay ability using an explicit FGameplayAbilitySpecHandle pointer lookup.

2. Logarithmic Time: $O(\log n)$

Raw C++ Structural Pattern

  • The Mechanism: Divide-and-conquer navigation. The data structure is organized hierarchically. At every single algorithmic step, the system evaluates a condition that disqualifies exactly half of the remaining uninspected dataset.
  • Structural Layout: Loop structures where the tracking counter multiplies or divides itself on each cycle (e.g., cutting the search window index in half) rather than incrementing sequentially by one.

Unreal Engine Framework Architecture

  • Spatial Partitioning Queries: Querying line-traces or sweep checks through the scene proxy octree. The engine discards entire quadrants of the map instantly if the ray does not intersect their bounding boxes.
  • Algo::BinarySearch: Using the built-in algorithmic utilities to find a specific data entry inside a TArray that has already been sorted.

3. Linear Time: $O(n)$

Raw C++ Structural Pattern

  • The Mechanism: Full sequential collection traversal. The algorithm begins at the head memory address and sequentially evaluates every single isolated data member until it hits the tail boundary.
  • Structural Layout: A single standard loop structure passing from index $0$ to boundary $N$, incrementing by a flat constant on every pass.

Unreal Engine Framework Architecture

  • World Iterators: Scanning the active level for specific actor types using TActorIterator or FObjectIterator.
  • TryActivateAbilityByClass: Triggering an ability by passing a class type. The engine executes a sequential loop down your character's active ability array, inspecting each spec one-by-one until a matching type profile is identified.
  • Uncached Tag Queries: Checking if a complex unindexed container has a specific gameplay tag by parsing raw string or hierarchical structures linearly.

4. Linearithmic Time: $O(n \log n)$

Raw C++ Structural Pattern

  • The Mechanism: N-scaled hierarchical sorting. The system repeatedly subdivides a messy collection into individual elements ($\log n$ splitting stages) and then systematically compares and merges those sub-collections back together ($n$ structural steps).
  • Structural Layout: Typically manifested as recursive functions that split data boundaries or balanced nested loops where an outer sorting pass coordinates with an inner partitioning pass.

Unreal Engine Framework Architecture

  • Algo::Sort: Sorting a TArray of hit results by distance, or organizing structural combat priorities (like determining which target in a radius has the lowest health percentage).
  • Render Proxy Updates: Re-organizing primitive draw calls or sorting translucent sorting layers on the render thread during complex frame passes.

5. Quadratic Time: $O(n^2)$

Raw C++ Structural Pattern

  • The Mechanism: Brute-force cross-multiplication. Every single active item in dataset A must fully interact with, check, or evaluate every single active item in dataset B. If dataset A and B are the same collection, it checks everything against itself.
  • Structural Layout: Deeply nested loops where the inner loop's total execution count is explicitly bound to the outer loop's input scale factor ($N$).

Unreal Engine Framework Architecture

  • Naive Collision Clusters: Running a manual overlap check where every single custom projectile actor loops through and tracks its distance against every other projectile actor on the field without utilizing a spatial tree layer.
  • Unoptimized Combo Matrix Parsing: A combat system that evaluates input sequences by comparing every single item in a dynamic structural history buffer against every single valid combo tree entry on every single tick.

Two-Way Explanation

Simple

Big O predicts scaling. Real performance depends on hardware. A linked list (O(1) insert) can be slower than a vector (O(n) insert) because vectors are cache-friendly and linked lists scatter memory everywhere. Profile your code. Don't trust Big O alone. The fastest algorithm on paper loses if it thrashes the cache.

Technical

Algorithmic complexity ignores memory hierarchy effects. A TArray::RemoveAt (O(n) due to element shift) can outperform a TLinkedList::Remove (O(1) pointer swap) because the TArray keeps elements contiguous — benefiting from spatial locality, prefetching, and SIMD. The crossover point depends on element size, cache line count, and access patterns. Always measure with real data sizes and real hardware.
