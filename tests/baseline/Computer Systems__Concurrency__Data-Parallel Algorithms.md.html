Data-Parallel Algorithms — Parallel For, Reduce, and Transform

> Why This Matters. The most scalable concurrent pattern is data parallelism: dividing a dataset across threads and applying the same operation independently. No locks, no contention, no deadlocks — just data partitioning. This is how physics engines process 10,000 rigid bodies per frame, how particle systems update millions of particles, and how AI evaluates hundreds of behavior trees simultaneously. This note covers the fundamental data-parallel patterns and their implementations.

Prerequisites

> [!info] Prerequisites > Understand thread pools (03 — SMT, Affinity & Thread Pools (coming soon)), cache lines and false sharing (../Hardware/05 — Memory Hierarchy (coming soon)), and Amdahl's/Gustafson's Laws (12 — Concurrency — Chapter Summary (coming soon)).

1. The Data Parallelism Model

Not "Threads" but "Work"

Data parallelism decomposes the data rather than the control flow: 
// ❌ TASK PARALLEL: design varying, cannot scale automatically

std::thread t1([&]{ SimulatePhysics(); });
std::thread t2([&]{ UpdateAnimations(); });
std::thread t3([&]{ ProcessAI(); });

// ✅ DATA PARALLEL: one kernel, many data slices

parallel_for(0, 10000, [&](int i) {
 particles[i].velocity += gravity * dt;
 particles[i].position += particles[i].velocity * dt;
});
```

### The Three Fundamental Patterns

| Pattern | Description | Example |
|---------|-------------|---------|
| **Map / parallel_for** | Apply a function to each element independently | `particles[i].Update()` |
| **Reduce** | Combine all elements into a single value | `sum = Σ positions[i]` |
| **Scan (prefix sum)** | Each element depends on previous elements | `prefix[i] = Σ data[0..i]` |
| **Transform** | Two input arrays → one output | `C[i] = A[i] + B[i]` |
| **Gather / Scatter** | Non-contiguous read/write | `result[index[i]] = data[i]` |

## 2. Parallel For — The Workhorse

### The Simplest Implementation

```cpp
void parallel_for(int start, int end, std::function<void(int)> func) {
 int num_threads = std::thread::hardware_concurrency();
 int chunk_size = (end - start) / num_threads;
 std::vector<std::thread> threads;
 
 for (int t = 0; t < num_threads; t++) {
     int chunk_start = start + t * chunk_size;
     int chunk_end = (t == num_threads - 1) ? end : chunk_start + chunk_size;
     threads.emplace_back([&, chunk_start, chunk_end] {
         for (int i = chunk_start; i < chunk_end; i++) {
             func(i);
         }
     });
 }
 for (auto& t : threads) t.join();
}
```

### Problems with Static Partitioning

If the workload is uneven (some particles do more work than others), static partitioning wastes time:

```cpp
// Particle 0-999: complex collision detection (100 µs each)

// Particle 1000-1999: simple movement (1 µs each)

// Thread 0: 1000 particles × 100 µs = 100 ms

// Thread 1: 1000 particles × 1 µs  = 1 ms

// Total time: 100 ms (bottlenecked by slowest chunk)

```

### Dynamic Partitioning (Work Stealing)

```cpp
class ParallelFor {
 std::atomic<int> next_index{0};  // Shared counter for dynamic work

 int end;
 
public:
 void Run(int start, int end, auto func) {
     this->end = end;
     next_index.store(start);
     
     int num_threads = std::thread::hardware_concurrency();
     std::vector<std::thread> threads;
     for (int t = 0; t < num_threads; t++) {
         threads.emplace_back([&, func] {
             while (true) {
                 int i = next_index.fetch_add(1);
                 if (i >= end) break;
                 func(i);
             }
         });
     }
     for (auto& t : threads) t.join();
 }
};
// Now fast chunks claim more iterations than slow chunks — load balanced!

```

**But:** `fetch_add(1)` on every iteration is expensive (~15 cycles). In practice, each thread grabs a **chunk** (e.g., 64 iterations) atomically, then processes them non-atomically.

## 3. Parallel Reduce

Combining all elements into one value requires per-thread partial results + final merge:

```cpp
template<typename T>
T parallel_reduce(const T* data, size_t n, T identity, auto combine) {
 int num_threads = std::thread::hardware_concurrency();
 std::vector`<T>` partials(num_threads, identity);
 
 parallel_for(0, n, [&](int i) {
     int tid = GetThreadId();
     partials[tid] = combine(partials[tid], data[i]);
 });
 // WARNING: false sharing on partials array!

 
 // Final sequential merge

 T result = identity;
 for (int t = 0; t < num_threads; t++) {
     result = combine(result, partials[t]);
 }
 return result;
}
```

### Fixing False Sharing

```cpp
struct alignas(64) AlignedPartial {
 T value;
};
std::vector`<AlignedPartial>` partials(num_threads);
// Each partial is on its own cache line — no false sharing!

```

### Associativity Matters

Parallel reduce requires the `combine` operation to be **associative**:

```cpp
// ASSOCIATIVE: (a + b) + c == a + (b + c) — parallel reduce is correct

int result = parallel_reduce(data, n, 0, std::plus<int>());

// NON-ASSOCIATIVE: floating point!

// (a + b) + c != a + (b + c) in general (rounding)

float result = parallel_reduce(floats, n, 0.0f, std::plus<float>());
// Results will differ between 1-thread and 4-thread runs!

```

## 4. Parallel Scan (Prefix Sum)

A prefix sum converts `[a0, a1, a2, a3, ...]` to `[a0, a0+a1, a0+a1+a2, ...]`. This is the foundation of radix sort, stream compaction, and segmented reductions.

### The Hillis-Steele Scan (Parallel)

```cpp
__global__ void ParallelScan(int* data, int n) {
 __shared__ int temp[1024];
 temp[threadIdx.x] = data[blockIdx.x * 1024 + threadIdx.x];
 __syncthreads();
 
 for (int stride = 1; stride < n; stride *= 2) {
     int val = 0;
     if (threadIdx.x >= stride) {
         val = temp[threadIdx.x - stride];
     }
     __syncthreads();
     temp[threadIdx.x] += val;
     __syncthreads();
 }
 
 data[blockIdx.x * 1024 + threadIdx.x] = temp[threadIdx.x];
}
```

This is O(n log n) work with O(log n) steps — more parallelism than a sequential scan (O(n)) but more total work.

## 5. Intel TBB — A Production Implementation

```cpp
#include <tbb/tbb.h>

// parallel_for with automatic work stealing

tbb::parallel_for(0, 10000, [&](int i) {
 particles[i].Update();
});

// parallel_reduce with automatic parallelism

float sum = tbb::parallel_reduce(
 tbb::blocked_range<int>(0, n),
 0.0f,
 [&](const tbb::blocked_range<int>& r, float init) -> float {
     for (int i = r.begin(); i < r.end(); i++) {
         init += data[i];
     }
     return init;
 },
 std::plus<float>()
);
```

### Choosing the Grain Size

```cpp
// Automatic grain size (TBB picks based on estimated cost)

tbb::parallel_for(
 tbb::blocked_range<int>(0, n),
 [&](const tbb::blocked_range<int>& r) {
     for (int i = r.begin(); i < r.end(); i++)
         data[i] = Process(data[i]);
 });

// Manual grain size for fine control

tbb::parallel_for(
 tbb::blocked_range<int>(0, n, 256),  // 256 elements per chunk

 [&](const tbb::blocked_range<int>& r) {
     // ...

 });
```

## Two-Way Explanation

### Simple

Data parallelism means: split a big array into chunks, give each chunk to a thread, run the same function on every element. No mutexes needed because each thread writes to different memory. The three basic patterns are: **parallel_for** (do something to every element), **reduce** (combine all elements into one number), and **scan** (compute running totals). The key challenge is load balancing — if some elements take longer to process, you want threads that finish early to steal work from threads that are still busy. This is "work stealing" and it's what TBB, OpenMP, and UE5's TaskGraph use internally.

### Technical

Data-parallel algorithms are expressed as monoid operations: an associative binary operation with an identity element. `parallel_for` is trivially data-parallel (no combining needed). `parallel_reduce` uses a tree: each thread computes a partial reduction on its chunk, then chunks are combined hierarchically (O(log P) steps for P threads). `parallel_scan` uses the Blelloch or Hillis-Steele algorithm; the latter is O(n log n) work with O(log n) steps. Optimal grain size balances the overhead of work stealing (~100-200 cycles per steal) against the cost of processing a chunk ~10,000-100,000 cycles. False sharing in the partials array is mitigated with cache-line padding (`alignas(64)`). TBB implements work stealing with per-thread deques (Chase-Lev), where the owner pops from one end and thieves steal from the other.
