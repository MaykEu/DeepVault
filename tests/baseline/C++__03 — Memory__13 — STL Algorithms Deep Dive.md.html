STL Algorithms Deep Dive

Prerequisites: Iterators & Algorithms (coming soon) — this note assumes you know the basic iterator/algorithm separation, std::find, std::sort, std::for_each, and iterator categories. std::vector (coming soon) for the data structures algorithms operate on.

Why This Matters
The STL has ~100 algorithms. Most C++ programmers use maybe 10. The other 90 exist because they solve problems you're currently solving by hand — with loops that are buggier, slower, and harder to read. std::lower_bound is a binary search you don't have to write (or get wrong). std::partial_sort gives you the top-10 scores in O(N log K) instead of O(N log N). std::inclusive_scan is a GPU-grade parallel prefix sum. This note is your map to the algorithms you don't know you need — organized by what you're trying to DO, not by header file.

Sorting Family — Beyond std::sort

std::sort — The Default (O(N log N), Introsort)

std::vector<int> v = {5, 2, 8, 1, 9};
std::sort(v.begin(), v.end()); // {1, 2, 5, 8, 9}
// With custom comparator:
std::sort(v.begin(), v.end(), std::greater{}); // descending
// C++20: projection avoids writing a comparator
std::vector<Player> players;
std::ranges::sort(players, {}, &Player::score); // sort by score, ascending

Introsort: starts as quicksort, switches to heapsort if recursion too deep — guarantees O(N log N) worst case.

std::stable_sort — Preserve Equal-Element Order (O(N log² N))

struct Task { int priority; std::string name; };
std::vector<Task> tasks = {{1, "A"}, {3, "C"}, {1, "B"}};
std::sort(tasks.begin(), tasks.end(),
 [](auto& a, auto& b) { return a.priority < b.priority; });
// Result: {A, B, C} — but A and B may swap! sort is NOT stable.
std::stable_sort(tasks.begin(), tasks.end(),
 [](auto& a, auto& b) { return a.priority < b.priority; });
// Result: {A, B, C} — A before B guaranteed. stable_sort preserves input order for equal keys.

Use stable_sort when: Equal elements have meaning (ties in leaderboard should preserve registration order).

std::partial_sort — Top-K Elements (O(N log K))

// Get the top 5 scores from 1,000,000 players:
std::vector<int> scores(1000000); // ... filled ...
std::partial_sort(scores.begin(), scores.begin() + 5, scores.end(), std::greater{});
// First 5 elements are the top 5 scores. Rest are unspecified order.

This is dramatically faster than std::sort when K << N. Instead of O(N log N), it's O(N log K). For K=5, N=1M: partial_sort does ~5M comparisons vs sort's ~20M.

Game use: Top-10 leaderboard, 5 nearest enemies, 3 highest-damage abilities.

std::nth_element — Find the Kth Element (O(N) average)

// Find the median without sorting everything:
std::vector<int> v = {9, 3, 7, 1, 5, 8, 2, 6, 4};
auto mid = v.begin() + v.size() / 2;
std::nth_element(v.begin(), mid, v.end());
// *mid is the median. Elements before are ≤ median. Elements after are ≥ median.
// Neither side is sorted — just partitioned.

Game use: Find the damage threshold that separates the top 50% of players from the bottom 50%.

Searching Family

On Sorted Ranges — Binary Search

std::vector<int> v = {1, 3, 5, 7, 9, 11, 13};
// Does the value exist? (bool)
bool found = std::binary_search(v.begin(), v.end(), 7); // true
// Where would 6 go? (iterator to first element ≥ 6)
auto it = std::lower_bound(v.begin(), v.end(), 6); // points to 7 (first ≥ 6)
size_t idx = std::distance(v.begin(), it); // idx = 3
// Where would 7 go? (iterator to first element > 7)
auto it2 = std::upper_bound(v.begin(), v.end(), 7); // points to 9 (first > 7)
// Both at once: [lower, upper) — all elements equal to 7
auto [lo, hi] = std::equal_range(v.begin(), v.end(), 7);
// lo points to 7, hi points to 9. count = hi - lo = 1

The trap: std::binary_search returns bool — it doesn't tell you WHERE the element is. Use lower_bound when you need the position.

The Equivalence Rule

lower_bound uses !(a < b) && !(b < a) — equivalence, NOT equality. This means lower_bound with a custom comparator that sorts by priority will find elements with the same priority, even if other fields differ.

std::vector<Task> tasks = sort_by_priority(tasks);
auto it = std::lower_bound(tasks.begin(), tasks.end(), 5,
 [](const Task& t, int p) { return t.priority < p; });
// Finds first task with priority ≥ 5, regardless of name

On Unsorted Ranges

std::vector<int> v = {3, 1, 4, 1, 5, 9};
// Find first occurrence (linear)
auto it = std::find(v.begin(), v.end(), 4); // O(N)
// Find first matching predicate
auto it2 = std::find_if(v.begin(), v.end(), [](int x) { return x > 5; }); // 9
// Find first NOT matching
auto it3 = std::find_if_not(v.begin(), v.end(), [](int x) { return x < 10; });
// Find any of several values
std::vector<int> targets = {4, 9};
auto it4 = std::find_first_of(v.begin(), v.end(), targets.begin(), targets.end());
// Find a subsequence (like string search for any type)
std::vector<int> pattern = {1, 5};
auto it5 = std::search(v.begin(), v.end(), pattern.begin(), pattern.end());
// Finds {1, 5} starting at position 3 (the "1" at index 3, followed by 5 at index 4)
// Boyer-Moore searcher (C++17) — faster for large patterns:
auto searcher = std::boyer_moore_searcher(pattern.begin(), pattern.end());
auto it6 = std::search(v.begin(), v.end(), searcher);

Heap Operations — Priority Queue Without std::priority_queue

std::priority_queue wraps a container and gives you .push()/.pop()/.top(). The heap algorithms give you DIRECT control over the underlying container:

std::vector<int> v = {3, 1, 4, 1, 5, 9};
// Build a max-heap in-place: O(N)
std::make_heap(v.begin(), v.end());
// v = {9, 5, 4, 1, 1, 3} — heap property: parent ≥ children
// Insert: push_back + push_heap: O(log N)
v.push_back(10);
std::push_heap(v.begin(), v.end());
// Extract max: pop_heap moves max to end, then pop_back: O(log N)
std::pop_heap(v.begin(), v.end()); // largest moves to v.back()
int max = v.back();
v.pop_back();
// Sort the heap: O(N log N)
std::sort_heap(v.begin(), v.end()); // ascending order

Why use heap algorithms over std::priority_queue? You can't iterate a priority_queue. With heap algorithms, you can std::find the heap, modify elements in-place (then make_heap again), or use a small vector and avoid the queue's wrapping.

Game use: Dijkstra's algorithm (open set = min-heap), A* pathfinding, event scheduler (earliest event first with min-heap). Use std::greater{} for a min-heap:

std::make_heap(v.begin(), v.end(), std::greater{}); // min-heap

Permutations

std::string s = "123";
// Generate the next lexicographic permutation:
do {
 std::cout << s << '\n'; // 123, 132, 213, 231, 312, 321
} while (std::next_permutation(s.begin(), s.end()));
// Previous permutation:
std::prev_permutation(s.begin(), s.end());

Game use: Generate all possible team compositions, test all weapon attachment combinations, brute-force solve small puzzles.

Numeric Algorithms ()

Reduction — Fold a Range Into a Single Value

std::vector<int> v = {1, 2, 3, 4, 5};
// Sum: O(N)
int sum = std::accumulate(v.begin(), v.end(), 0); // 15
// Product with custom op: O(N)
int prod = std::accumulate(v.begin(), v.end(), 1, std::multiplies{}); // 120
// C++17: parallel-friendly reduce (no guaranteed order — faster)
int sum2 = std::reduce(std::execution::par, v.begin(), v.end(), 0);

accumulate vs reduce: accumulate does LEFT-fold (guaranteed order). reduce may reorder for parallelism. Use reduce when the operation is associative and commutative (addition, multiplication) and you're on large data.

Prefix Sum (Scan) — Each Element = Sum of Predecessors

std::vector<int> v = {1, 2, 3, 4, 5};
std::vector<int> result(5);
// Exclusive scan: result[i] = sum of v[0..i-1]
std::exclusive_scan(v.begin(), v.end(), result.begin(), 0);
// result = {0, 1, 3, 6, 10}
// Inclusive scan: result[i] = sum of v[0..i]
std::inclusive_scan(v.begin(), v.end(), result.begin());
// result = {1, 3, 6, 10, 15}

Game use: Compute running totals (cumulative damage dealt in a match), prefix-min for water-rendering depth queries, GPU-style parallel prefix sum for particle systems.

Other Numeric Algorithms

// Inner product (dot product): a₁·b₁ + a₂·b₂ + ...
double dot = std::inner_product(a.begin(), a.end(), b.begin(), 0.0);
// Partial sum: each output = sum of input up to that point
std::partial_sum(v.begin(), v.end(), result.begin());
// v={1,2,3} → result={1,3,6}
// Adjacent difference: result[i] = v[i] - v[i-1]
std::adjacent_difference(v.begin(), v.end(), result.begin());
// v={1,3,6} → result={1,2,3} (first element unchanged)
// Fill with incrementing values (C++11):
std::iota(v.begin(), v.end(), 0); // v = {0, 1, 2, 3, ...}

Memory Algorithms ()

Operate on UNINITIALIZED memory — crucial for custom containers:

// Allocate raw memory (no constructors called):
alignas(T) std::byte buffer[sizeof(T) * N];
// Construct objects in raw memory:
std::uninitialized_fill(buffer_begin, buffer_end, T{42});
std::uninitialized_copy(source.begin(), source.end(), buffer_begin);
std::uninitialized_move(source.begin(), source.end(), buffer_begin);
// Default-construct in raw memory:
std::uninitialized_default_construct(buffer_begin, buffer_end);
std::uninitialized_value_construct(buffer_begin, buffer_end); // zero-init first
// Destroy objects (calls destructors, doesn't free memory):
std::destroy(buffer_begin, buffer_end);
std::destroy_at(&buffer[3]); // single element
// C++17: destroy N elements
std::destroy_n(buffer_begin, N);

Game use: Every custom container (SmallVector, arena-backed vector, ring buffer) calls these.

Algorithms and Iterator Categories

Every algorithm has minimum iterator requirements:

Iterator CategorySupportsTypical ContainerAlgorithms That Need It
Input*it (read once), ++itstd::istream_iteratorfind, count, for_each, accumulate
ForwardInput + multi-pass (can copy iterator)std::forward_listadjacent_find, search, unique
BidirectionalForward + --itstd::list, std::setreverse, partition
Random AccessBidirectional + it+n, it-n, <, >, <=, >=std::vector, std::dequesort, nth_element, binary_search, heap ops
Contiguous (C++17)Random Access + elements in contiguous memorystd::vector, std::array, std::spanOptimization hint for memcpy/vectorization
The trap: Calling std::sort on a std::list doesn't compile — std::list::iterator is bidirectional, not random-access. Use list.sort() member function instead.

Two-Way Explanation

Beginner: The STL algorithms library is a toolbox for operating on ranges of elements. Instead of writing a for loop to find something, use std::find. Instead of writing your own sort, use std::sort. These are tested, optimized, and express intent better than raw loops. The key families: sorting (sort, partial_sort for top-K), searching (binary_search, lower_bound for position), heap operations (priority queue without the wrapper), and numeric (accumulate for sum, inclusive_scan for running totals). Each algorithm documents its complexity — O(N log N) for sort, O(N) for nth_element, O(log N) for binary_search.

Experienced: STL algorithms are organized by iterator category requirements. Non-mutating algorithms (find, count, for_each) accept Input iterators. Mutating algorithms (copy, transform, generate) accept Output iterators. Sorting and partitioning require Random Access iterators. The numeric algorithms () include parallel-enabled overloads (std::reduce vs std::accumulate) with C++17 execution policies. Heap algorithms (make_heap, push_heap, pop_heap, sort_heap) operate on Random Access ranges with O(log N) per operation — they provide the underlying mechanism for std::priority_queue. Memory algorithms (uninitialized_, destroy_) are the building blocks for custom containers — they separate allocation from construction, enabling SSO, arena allocation, and relocation optimizations. std::search with a Boyer-Moore searcher (C++17) provides sublinear average-case pattern matching.

Exercises

  1. Top-K leaderboard: Generate 1,000,000 random scores. Use partial_sort to get the top 10. Now use nth_element to find the 100,000th highest score (top 10% threshold). Time both. Which is faster for which K?
  1. Binary search on game data: Create a std::vector sorted by minLevel. Use lower_bound to find the spawn at level 42. Handle the case where no spawn exists exactly at 42. Write equal_range to find all spawns in level range [40, 50].
  1. Heap-based event scheduler: Implement an event system where events have float triggerTime. Use std::make_heap with min-heap. Insert new events with push_heap. Process events by popping from heap until current time. Why use heap algorithms instead of std::priority_queue?
  1. Prefix sum for damage attribution: A match has 10,000 damage events. Compute the cumulative damage at each event using std::inclusive_scan. Now find the event index where cumulative damage first exceeds 50% of total using lower_bound on the scan result.
  1. Custom container constructor: Write a SmallVector that uses std::uninitialized_fill for its inline buffer and std::destroy in the destructor. Why can't you just use new/delete?
