DeepVault Cross-Cutting Quality Standards

Every vault note must include ALL of the following:

1. Learning Objectives (2-3 lines, top of note after title)

Format:
Learning Objectives
After this note, you will be able to:
- [specific, measurable skill]
- [specific, measurable skill]
- [specific, measurable skill]

2. Why This Matters (3-5 paragraphs, after prerequisites)

Format:

Why This Matters. [Concrete, memorable story of a real bug, performance issue, or architectural decision that this note solves.]

Every note MUST have this. If missing, add one.

3. Prerequisites Callout

Format:
Prerequisites
- Link to Note 1 (coming soon) — brief reminder of what you need
- Link to Note 2 (coming soon) — brief reminder

4. Two-Way Explanation (end of note, before exercises)

Two sections:

Simple — for beginners

[One paragraph: analogy-first, no jargon beyond what's defined in the note]

Technical — for experienced readers

[One paragraph: precise terminology, includes at least one specific number (cycle count, byte count, latency)]

5. Common Pitfalls (before Two-Way Explanation)

Format:

Common Pitfalls

  • Pitfall Name: [explanation of the mistake]. Fix: [how to do it right].
  • Pitfall Name: [explanation of the mistake]. Fix: [how to do it right].

6. Exercises (5 exercises per note)

Pattern:
  1. Conceptual (must have read the note to answer)
  2. Code-writing (write actual C++/assembly)
  3. Analysis (investigate, compare, evaluate)
  4. Real-world (UE5/game dev context)
  5. Design (architectural decision)

7. See Also (bottom of note)

Wiki-links to related notes.

8. ARM Equivalents

For every x86 instruction/technique used, add ARM equivalent in a callout:
ARM Equivalent
x86_instruction → ARM_instruction. Key differences: [1-sentence].

9. C++ Version Callouts

For every std:: primitive, add the C++ version it was introduced in: std::jthread (C++20), std::atomic (C++11), etc.

10. Deep Dive Labels

Mark complex sections that can be skipped on first read:

Deep Dive — Can skip on first read.
